# xkeen-subscription-watcher

Форк [tkukushkin/xkeen-subscription-watcher](https://github.com/tkukushkin/xkeen-subscription-watcher) для обновления подписок Xray с постоянными тегами маршрутизации и Hysteria2 + Salamander.

## Возможности форка

- `hysteria2://` и `hy2://`: полный auth (включая `user:password`), SNI, ALPN и Salamander через native Xray `finalmask.udp`.
- Явная карта тегов: адреса и пароли меняются, выбранные теги маршрутизации сохраняются.
- Обновление выбранных профилей внутри существующего `04_outbounds.json`. Остальные профили, их порядок и другие поля документа сохраняются; файлы маршрутизации не редактируются.
- Проверка полного кандидата установленным Xray до применения, приватные резервные копии, блокировка параллельных запусков и проверка изменений файла другим процессом.
- В управляемом режиме ошибка применения вызывает восстановление прежних outbounds; ошибки восстановления явно возвращаются.
- URL подписки можно читать из файла. URL, auth и ответы сервера подписки не выводятся в лог.

Обновляются параметры выбранных серверов. Выбор другого сервера при недоступности настраивается отдельно. Для фиксированных маршрутов балансировщик не требуется.

## Сборка и установка

Нужен Go версии из `go.mod`. Для arm64:

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags='-s -w' -o xkeen-subscription-watcher-linux-arm64 .
```

Скопируйте подходящий бинарник в `/opt/sbin/xkeen-subscription-watcher`, права `0755`. После публикации релиза форка готовый бинарник можно установить через `install.sh`: он загружает релизы **alexbuckner/xkeen-subscription-watcher**. Бинарники исходного проекта не содержат доработок этого форка.

## Обновление существующих тегов

1. Сохраните URL подписки одной строкой в `/opt/etc/xray/subscription.url`, права `0600`. Этот файл хранится вне публичного репозитория.
2. Подготовьте `tags.json`, например [examples/stable-tags.json](examples/stable-tags.json):

```json
{
  "rules": [
    {"name": "*SE #4*", "protocol": "hysteria2", "tag": "hysteria2-se4"},
    {"name": "*USA*VA, Manassas*", "protocol": "vless", "network": "tcp", "security": "reality", "tag": "vless-reality-us9", "flow": "xtls-rprx-vision-udp443"},
    {"name": "*India*", "protocol": "vless", "network": "tcp", "security": "reality", "tag": "vless-reality-in1", "flow": "xtls-rprx-vision-udp443"}
  ]
}
```

`name` — маска полного декодированного названия (`*`, `?`, `[...]`, без учёта регистра). `protocol` обязателен; `hy2` равнозначен `hysteria2`. `network` и `security` уточняют профиль; `tcp` и `raw` равнозначны. Необязательный `flow` явно сохраняет выбранный локально режим VLESS.

Каждое правило должно найти ровно один профиль после фильтрации. Повтор одной URI-строки игнорируется; разные совпадающие профили считаются неоднозначностью. Если узел пропал, неоднозначен или не разбирается, весь управляемый запуск завершается с ошибкой до записи и API-вызовов. Целевые теги должны уже существовать в обновляемом файле.

3. Проверьте изменения:

```sh
/opt/sbin/xkeen-subscription-watcher --tag provider \
  --url-file /opt/etc/xray/subscription.url \
  --tag-map /opt/etc/xray/tags.json \
  --update-file 04_outbounds.json \
  --no-hwid --dry-run
```

`--tag-map` и `--update-file` используются вместе. `--update-file` — имя файла внутри `--output-dir` (по умолчанию `/opt/etc/xray/configs`). Обновляются только перечисленные в карте профили; остальные сохраняются, новые узлы автоматически не добавляются. Нативная проверка обязательна. Для ресурсов Xray должны сохраняться его обычные переменные окружения, например `XRAY_LOCATION_ASSET`.

При обновлении того же протокола сохраняются локальные параметры outbound вне данных подключения, `sockopt`, `packetEncoding`, `level`/`email` единственного пользователя VLESS/VMess и настройка keepalive Hysteria. Параметры сервера, auth и TLS берутся из подписки; явный `flow` — из карты тегов.

`--dry-run` не записывает конфиги, не создаёт резервных копий и не вызывает API. `--no-restart` имеет другое значение: записать результат на диск без применения к работающему Xray.

## Применение через API

В Xray нужен локальный `HandlerService`, например отдельный `00_api.json`:

```json
{"api":{"tag":"api","listen":"127.0.0.1:10085","services":["HandlerService"]}}
```

После первоначального включения API требуется один перезапуск Xray. Затем уберите `--dry-run` из проверенной команды: watcher заменяет изменившиеся outbounds через API без полного перезапуска XKeen. Замена активного outbound может затронуть использующие его соединения; бесшовность не гарантируется.

Перед изменением старый файл сохраняется в `subscription-backups` рядом с каталогом конфигов. `--backup-dir` задаёт другой каталог вне `--output-dir`. На Linux каталоги получают права `0700`, копии и новые конфиги — `0600`. Копии содержат секреты; срок хранения выбирает владелец.

После успешной ручной проверки добавьте ту же команду в cron, например раз в час:

```crontab
0 * * * * XRAY_LOCATION_ASSET=/opt/etc/xray/dat /opt/sbin/xkeen-subscription-watcher --tag provider --url-file /opt/etc/xray/subscription.url --tag-map /opt/etc/xray/tags.json --update-file 04_outbounds.json --no-hwid
```

Блокировка `.subscription-watcher.lock` предотвращает параллельные запуски. После аварийного завершения оставшийся lock-файл удаляют только после проверки, что предыдущий процесс завершён.

## Остальные параметры

Сохранена поддержка VLESS, VMess, Trojan и Shadowsocks исходного проекта. Фильтры `--include` / `--exclude`, `--single-proxy`, `--dialer-proxies` и `--reality-fingerprint` доступны в обычном режиме генерации `04_outbounds.<tag>.json`. Карта тегов требует одну подписку и несовместима с `--single-proxy` / `--dialer-proxies`.

Hysteria2 поддерживает `sni`, `alpn`, `security=tls`, `insecure=0|1`, `obfs=salamander`, `obfs-password`, IPv6 и порт по умолчанию `443`. Другие параметры, включая port hopping, `pinSHA256`, ECH и другую обфускацию, отклоняются вместо молчаливой потери. Ограничения Xray проверяются нативно: например Xray 26.6.1 отклоняет `allowInsecure=true` после 2026-06-01. Проверка сертификатов не отключается автоматически.

- `--url`: URL в аргументах вместо `--url-file`; для секретной ссылки предпочтителен файл.
- `--validate`: проверять полный кандидат также в обычном режиме генерации.
- `--no-hwid`: не получать и не отправлять HWID Keenetic. Без флага сохраняется поведение исходного проекта.

Для нативных интеграционных тестов задайте `XRAY_BINARY` и выполните `go test ./...`. Тесты используют вымышленные адреса и пароли. Linux CI также запускает race detector.
